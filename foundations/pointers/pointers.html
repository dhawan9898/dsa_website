Pointers in C

A pointer is just a variable whose value happens to be a memory address — nothing more mysterious than that.

Notes

Every variable lives somewhere in memory, at its own address. A pointer is just a variable whose value is one of those addresses — int *p declares p as "a pointer to an int," meaning whatever address it holds should have an int stored there. Two operators do all the work: &x means "give me x's address" (turns a variable into a pointer to it), and *p means "go to the address p holds and read (or write) what's stored there" — called dereferencing.

The single biggest reason pointers exist is that C passes arguments by value: a function gets its own copy of whatever you pass it, so changes inside the function never touch the caller's original variable — unless what you pass is an address. Passing &a instead of a still copies a value into the function (the address itself), but that copied address still points at the caller's real variable, so writing through it with *pa = ... changes the original. That's how the classic swap function below actually swaps two variables — no other way to do it in C.

Implementation: pointer arithmetic is exactly the address formula from Arrays & Memory — arr + i computes the same address as &arr[i], and *(arr + i) reads the same value as arr[i]. Array indexing in C isn't a separate mechanism from pointers; it's pointer arithmetic with friendlier syntax.

When it breaks: four classic bugs, all from treating an address as more trustworthy than it is. Dereferencing a NULL pointer (one explicitly set to point at nothing) crashes immediately — loud, but at least obvious. A dangling pointer — one that still holds the address of memory that's already been freed — is worse: the address looks valid, so *p might silently return garbage, or corrupt whatever now legitimately lives at that address, often far from the line that freed it. A memory leak is the mirror case: losing the only pointer to some allocated memory before freeing it means nothing can ever free it again. And an uninitialized pointer — declared but never set to point anywhere in particular — holds whatever garbage address happened to be sitting in memory, so dereferencing it is undefined behavior from the very first use.
