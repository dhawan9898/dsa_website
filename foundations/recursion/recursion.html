Recursion & the Call Stack

A function that calls itself, and the stack of pending calls that makes it work — and that you can overflow if you're not careful.

Notes

A recursive function solves a problem by calling itself on a smaller version of the same problem. Every recursive function needs exactly two parts: a base case — the smallest version of the problem, simple enough to answer directly, with no further recursion — and a recursive case that does a little work and then calls itself on something strictly closer to the base case. Miss either part and the function either never recurses at all, or never stops.

Every function call, recursive or not, gets its own stack frame: a chunk of memory holding that call's parameters, local variables, and the address to resume at when it returns. Calling a function pushes a new frame on top of the call stack; returning pops it back off and resumes the caller exactly where it left off. A recursive function just means the same function's frames stack up on top of each other, one per level of recursion still waiting on a result — which is exactly what the demo below makes visible: watch the boxes stack up as factorial(4) calls factorial(3) calls factorial(2)…, then unstack as each one finally gets a number back and returns it to whoever called it.

Implementation: the code panel below is as small as recursion gets — one comparison for the base case, one multiplication and one recursive call for everything else. Notice that factorial(4) can't produce its own answer until factorial(3) hands one back, which can't answer until factorial(2) does, all the way down to factorial(1) — the base case is the only frame that returns without waiting on anyone.

When it breaks: a missing base case, or one that's never actually reached (recursing on n + 1 instead of n - 1, say), means every call pushes another frame and none ever pop — the call stack is a fixed-size region of memory, not an infinite one, and running out of it is a real crash called stack overflow, the same term the Stack page uses for pushing past a fixed capacity. It's the same failure for the same underlying reason: more pushes than the stack has room for.

Recursion is the natural shape for anything that's already built recursively — trees (a subtree is just a smaller tree), divide-and-conquer sorts, graph traversal — which is why it shows up all over this site: BST and AVL insert/delete, merge sort's split-and-merge, quick sort's partition-and-recurse, and depth-first search on a graph.
