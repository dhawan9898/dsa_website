Pick a Pivot · Partition · Recurse

Quick Sort

Picks a pivot, partitions the range around it so everything smaller ends up on the left and everything larger on the right, then recurses on each side.

Notes

Quick sort also divides and conquers, but unlike merge sort it does the work before recursing, not after. Pick a pivot (the code below always uses the last element of the range), then partition: walk the range and shuffle everything ≤ the pivot to the left, everything greater to the right. Once the walk finishes, swap the pivot into the boundary between those two groups — it's now in its exact final sorted position, permanently, and the algorithm recurses into the two sides on either side of it.

CaseTime
AverageO(n log n)
Worst (already sorted, last-element pivot)O(n²)
SpaceO(log n) average — recursion stack only, sorts in place

Implementation: the code panel's partition step (Lomuto's scheme) tracks a single boundary index i: everything at or before i is known ≤ the pivot. Every time the scan finds another value that qualifies, i advances and that value swaps into place — one pass, one boundary, no extra array needed, which is why quick sort's space cost is just the recursion stack rather than merge sort's O(n) temporary buffer.

Common mistake: always picking the same position as pivot (the last element, as here) is what causes the O(n²) worst case — a sorted or reverse-sorted input keeps producing the most unbalanced possible split, one side of size n-1 every single time. Real implementations often pick a pivot at random, or the median of a few sampled elements, specifically to make that worst case astronomically unlikely rather than one sorted-input away.
