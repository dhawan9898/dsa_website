Merge Sort

Splits the array in half recursively down to single elements, then zips each pair of already-sorted halves back together in order.

Notes

Merge sort is a classic divide and conquer algorithm. Going down, it only cuts: split the range in half, recursively sort each half, and repeat until a range is down to a single element (which is trivially sorted already). No comparisons happen on the way down at all — the actual work is all on the way back up, where two already-sorted halves are merged into one sorted run by repeatedly taking whichever half's front value is smaller.

CaseTime
Every caseO(n log n) — log n levels of splitting, O(n) work merging each level
SpaceO(n) — needs a temporary array for the merge step

Implementation: the code panel below copies each half into its own temporary array, L and R, before merging — writing the merged result back into the original array while still reading from it would overwrite values the merge hasn't consumed yet. That temporary space is the one thing merge sort gives up to guarantee O(n log n) in every case, unlike quick sort, which is usually faster in practice but can degrade to O(n²) on unlucky input.

Common mistake: on a tie, always take from the left half first. Taking from the right on a tie still produces a correctly sorted array, but it silently breaks stability — two equal elements can end up swapped relative to their original order, which matters whenever you're sorting records by one field while relying on a previous sort's order for a tiebreaker.
