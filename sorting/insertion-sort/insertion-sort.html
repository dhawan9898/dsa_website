Insertion Sort

Builds a sorted prefix one element at a time. Each new value walks left past everything bigger than it until it finds its place.

Notes

Insertion sort grows a sorted prefix on the left, one element at a time — the way most people actually sort a hand of playing cards. Each new value, the key, is compared against the sorted prefix from right to left; every value larger than the key shifts one step right, and the key drops into the gap that opens up. After i passes, indices 0..i are guaranteed sorted, even though the rest of the array hasn't been touched yet.

CaseComparisonsTime
Worst (reverse sorted)~n²/2O(n²)
Best (already sorted)n−1O(n)
SpaceO(1) — sorts in place

Implementation: the code panel below implements the shift as a while loop that stops the instant it finds a value not greater than the key — that early stop is what makes the best case O(n): on an already-sorted array, every key immediately fails its very first comparison and never shifts at all. This is also why insertion sort is the standard choice for finishing off small partitions inside faster sorts like quicksort: on nearly-sorted data it's close to linear, and its overhead per element is tiny.

Common mistake: save the key's value (arr[i]) into a local variable before starting the shift loop. Skip that and the first shift overwrites arr[i] with its neighbour before the key's original value has been read anywhere else — it's silently gone, and the final placement writes back a duplicate instead of the real key.
