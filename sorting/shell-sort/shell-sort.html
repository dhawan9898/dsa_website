Shrink the Gap · Insert · Repeat

Shell Sort

Insertion sort's problem is that values only move one step at a time. Shell sort fixes that: compare far-apart elements first, then close the gap.

Overview Playground

The idea, in one picture

Insertion sort is slow on shuffled data because a value far from home has to shuffle left one slot at a time. Shell sort gives it a head start: first it runs insertion sort on elements that are a big gap apart, so a small value near the end can leap most of the way to the front in a single move. Then it shrinks the gap and repeats, and repeats, until the gap is 1 — an ordinary insertion sort, but now on data that's almost sorted, which insertion sort races through.

It's insertion sort, gap-strided. With gap = 4, it independently insertion-sorts the sub-sequences {a[0], a[4], a[8]…}, {a[1], a[5]…}, and so on. Each pass makes the array "more sorted" cheaply, so the final gap-1 pass has very little left to do.

The gap sequence matters. The simple "halve the gap each time" (shown here) is easy to grasp but not optimal; carefully chosen sequences (Hibbard, Sedgewick, Knuth) push the average toward O(n4/3) or better. Shell sort is adaptive, in place, and simple — a solid choice for medium-sized arrays and embedded code where you want better-than-O(n²) without the overhead of quick or merge sort. It is not stable.
