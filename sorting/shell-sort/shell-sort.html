Shrink the Gap · Insert · Repeat

Shell Sort

Insertion sort with a twist: compares elements far apart first, then shrinks that gap every pass until it reaches 1.

Notes

Plain insertion sort is fast on nearly-sorted data but slow whenever a small value starts out far from where it belongs — it has to shift past every value in between, one slot at a time. Shell sort's fix: run insertion sort on far-apart elements first. With a gap of g, it insertion- sorts every g-th element as its own interleaved sequence, moving badly-placed values a long way in a single swap. The gap then shrinks — typically halved — each pass, until it reaches 1, which is just an ordinary insertion sort pass, but over data that's now already close to sorted.

CaseTime
Depends on gap sequenceroughly O(n¹·³≈) for the halving sequence used here
SpaceO(1) — sorts in place

Implementation: the code panel below is exactly insertion sort with every 1 replaced by gap — the inner comparison, the shift, and the step all move by gap positions instead of one. That's the whole trick: no new mechanism, just insertion sort's existing shift logic running across a wider stride, shrunk pass by pass until the stride is 1 again.

Common mistake: forgetting that the final pass must bring the gap down to exactly 1 — skip it (say, by stopping once the gap rounds down to 0 one step early) and the array ends up only "mostly" sorted, since elements that were never compared within one gap of each other can still be out of order relative to one another.
