Heap Sort

Arranges the array into a max-heap, then repeatedly pulls the largest value from the root and re-heapifies what's left.

Notes

Heap sort borrows the binary heap's core operation, sift-down, and applies it twice over. First, build a max-heap out of the whole array in place: work backwards from the last non-leaf node to the root, sifting each one down so every parent ends up ≥ its children. Second, repeatedly extract: the root is always the largest remaining value, so swap it to the end of the unsorted region, shrink that region by one, and sift the new root down to restore the heap property — over and over until one element is left.

CaseTime
Every caseO(n log n) — n extractions, each an O(log n) sift-down
SpaceO(1) — the heap lives in the same array being sorted

Implementation: the code panel below stores the heap the same way the priority queue does — no pointers, just index arithmetic: node i's children live at 2i+1 and 2i+2. That's what makes heap sort's O(1) space possible where merge sort needs O(n): the sorted output grows at the end of the very array the heap is stored in, one extraction at a time, with nothing copied out.

Common mistake: sifting down from the root without first fixing up its children's subtrees. Sift-down only assumes the two child subtrees are already valid heaps — which is exactly why the build phase works backwards from the bottom up. Sifting forwards from the root on an unheapified array simply produces the wrong heap.
