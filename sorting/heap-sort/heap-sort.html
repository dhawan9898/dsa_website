Heap Sort

Turn the array into a max-heap, then repeatedly pull the biggest value off the top and drop it at the end.

Overview Playground

The idea, in one picture

Heap sort is selection sort with a better engine. Selection sort scans O(n) to find each maximum; heap sort keeps the values in a max-heap — a binary heap where every parent is larger than its children — so the maximum is always sitting at the root, free to grab in O(1). Pull it out, restore the heap in O(log n), and repeat.

It works in two phases, both in place: build the array into a max-heap, then extract — swap the root (the max) with the last heap slot, shrink the heap by one, and sift the new root down until the heap property holds again. Each extracted max lands just past the shrinking heap, so the sorted region grows from the right.

The heap lives in the array. No pointers, no second structure: the node at index i has children at 2i+1 and 2i+2. "Sift down" walks a value from a node toward the leaves, swapping it with its larger child until it's bigger than both.

Going deeper

cost and character
PhaseWhat it doesTime

Extract alln swaps, each with an O(log n) siftO(n log n)
Whole sortGuaranteed, in placeO(n log n)

Guaranteed O(n log n) and in place — heap sort never degrades to O(n²) like quick sort can, and needs no extra array like merge sort does. Its trade-offs: it's not stable, and its jumping around the array (parent to child to grandchild) has worse cache behaviour than quick sort, so it's often a touch slower in practice despite the same big-O. It shines when worst-case guarantees and O(1) extra space both matter.
