Bubble Sort

The simplest sort there is: keep swapping neighbours that are out of order, and the biggest values "bubble" to the end.

Overview Playground

The idea, in one picture

Imagine lining up cards and only ever comparing two side-by-side cards at a time. If the left one is bigger than the right, swap them. Sweep left-to-right doing that, and by the end of one sweep the single biggest card has been carried all the way to the right end — it "bubbled" up. Do another sweep and the second-biggest lands in place, and so on.

That's bubble sort: repeated passes of "compare each neighbour pair, swap if out of order." Each pass locks one more value at the end, so after enough passes the whole array is sorted.

The early-exit trick. If a whole pass makes zero swaps, nothing was out of order — the array is already sorted, and you can stop immediately. On an already-sorted array that makes bubble sort O(n): one clean pass and done.

Going deeper

cost and character
CaseWhenTime
BestAlready sorted (early exit)O(n)
Average / WorstRandom or reversedO(n²)
SpaceSwaps in placeO(1)

It's stable and in-place — equal values keep their relative order, and it needs no extra array. But those n² comparisons make it slow on anything large: it's a teaching sort, not a production one. For real work you'd reach for quick sort or merge sort (O(n log n)). Bubble sort earns its keep as the clearest possible introduction to "compare and swap," and its cousin insertion sort is the one simple O(n²) sort that's genuinely useful (fast on nearly-sorted data).
