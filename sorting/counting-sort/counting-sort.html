Counting Sort

No comparisons at all: count how often each value appears, turn those counts into output positions, then place every value directly where it belongs.

Notes

Every sort covered so far is comparison-based — it decides order by asking "is this bigger than that?" — and every comparison-based sort is provably at best O(n log n). Counting sort sidesteps the question entirely: if every value is a non-negative integer within some known range, you can count how many times each one appears, turn those counts into exact output positions with a running total, then place every value straight into its slot. No comparisons, no swaps — the trade is needing to know the value range up front, and paying for an array sized to it.

CaseTime
Every caseO(n + k), where k is the value range
SpaceO(n + k) — the count array plus the output array

Implementation: the code panel's middle loop — count[v] += count[v - 1] — turns raw occurrence counts into a running total, so count[v] ends up meaning "how many values are ≤ v", which is exactly the one-past-the-end output index for the last copy of v. The final loop walks the input backwards specifically so that when two equal values are placed, the one that appeared earlier in the input still lands in the earlier output slot — that's what makes counting sort stable.

Common mistake: walking the placement loop forwards instead of backwards still produces a correctly sorted array — every value lands in a valid slot for its size — but silently breaks stability, since equal values now land in reversed relative order. It's the same trap merge sort's tie-handling has, from the opposite direction.
