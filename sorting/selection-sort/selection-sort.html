Selection Sort

Each pass scans the unsorted remainder for its smallest value, then swaps that value into place at the front of the remainder.

Notes

Selection sort keeps a growing sorted prefix at the front of the array. Each pass scans the entire unsorted remainder to find its smallest value, then swaps that value into the next open slot — index i on pass i. Unlike bubble sort, which can perform many swaps in a single pass, selection sort performs at most one swap per pass: it only ever writes once it already knows exactly which value belongs at that slot.

Implementation: the code panel below tracks a single index, minIdx, through the whole inner scan — it's updated in memory every time a smaller candidate turns up, but nothing in the array itself moves until the scan finishes. That's the trade selection sort makes against bubble sort: the comparison count is identical (it still has to look at every remaining element every pass), but the write count drops from potentially O(n²) down to a hard O(n) ceiling, which matters when writes are expensive relative to reads.

Common mistake: because the swap only happens once per pass, it's tempting to swap immediately the moment a smaller value is found mid-scan — but that swaps the wrong value into place early and corrupts the rest of the scan. The candidate index has to be tracked and only swapped in after the full remainder has been checked.
