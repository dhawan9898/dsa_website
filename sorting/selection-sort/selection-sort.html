Selection Sort

Find the smallest value, put it first; find the next smallest, put it second; and so on — one exact placement per pass.

Overview Playground

The idea, in one picture

Sorting a hand of cards, you might scan for the smallest, pull it to the front, then scan the rest for the next smallest, and repeat. Selection sort is exactly that: each pass selects the minimum of the unsorted part and swaps it into the next sorted slot. After pass k, the first k positions hold the k smallest values, in order — and they never move again.

One swap per pass. Unlike bubble sort, which may swap many times per pass, selection sort scans to find the minimum and then makes a single swap. That's its one edge: it does the fewest writes of any simple sort — handy when writing to memory is expensive.

No early exit. Selection sort always scans the entire unsorted region to be sure it found the minimum, so it's O(n²) even on already-sorted input — no best-case shortcut like bubble or insertion sort. It's also not stable by default (a swap can leapfrog equal values). Its selling point is minimal writes; for speed on real data, use quick or merge sort.
