Binary Heap · Root Is Always Next

Priority Queue

A queue where what comes out next isn't who arrived first, but whoever has the highest priority.

Notes

A priority queue always hands back its highest-priority element first, regardless of insertion order. The standard way to build one is a binary heap: a complete binary tree (every level full except possibly the last, filled left to right) where every parent outranks its children — a max-heap keeps the largest value at the root, a min-heap the smallest.

Because it's always complete, a heap can be stored compactly in a plain array with no pointers at all: node i's children live at 2i+1 and 2i+2, and its parent at (i-1)/2. Insert appends a new leaf and sifts it up past any parent it outranks; extracting the root moves the last leaf into its place and sifts it down past whichever child outranks it, exactly the mechanics behind heap sort.

OperationWhat it doesTime
InsertAppend a leaf, sift it upO(log n)
ExtractRemove the root, move the last leaf there, sift it downO(log n)
PeekLook at the root without removing itO(1)

Used for Dijkstra's and Prim's algorithms (always expand the cheapest known option next), OS task schedulers, and event simulations that need to process the next-soonest event regardless of when it was scheduled.
