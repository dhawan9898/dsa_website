Plunge, Then Backtrack

Depth-First Search

The thought process

DFS is the opposite instinct to BFS: instead of spreading out evenly, it commits to a direction and goes as deep as possible before it ever looks sideways. When it hits a dead end (a vertex whose neighbours are all already seen), it backtracks to the last place it had another choice and tries that.

That plunge-and-backtrack rhythm is exactly what a stack does — and recursion uses the call stack automatically, which is why DFS is usually written as a tiny recursive function. Each call to dfs(u) is one vertex on the current path; when the call returns, you've backtracked off that vertex.

  1. Mark the current vertex seen (this counts as visiting it).
  2. For each neighbour that isn't seen, recurse into it — dive deeper.
  3. When every neighbour is handled, the call returns — that's the backtrack.
The stack strip below is the call stack. Every time DFS dives into a neighbour, that vertex is pushed; every time a call returns, it's popped. The path from the start down to the red vertex is exactly what's on the stack right now.

Reading the code

There's no explicit stack in the code — the recursion is the stack. Each dfs(g, v) call pauses the current one mid-loop, runs to completion for v, and then resumes exactly where it left off. Like BFS, the seen array makes each vertex processed once and each edge examined once, so DFS is also O(V + E).

BFS vs DFS, same graph, same start A: BFS visits A, B, D, C, E, F (nearest first); DFS visits A, B, C, F, E, D (deepest first). Same vertices, same cost — completely different order, and that order is what makes each one suited to different jobs.
