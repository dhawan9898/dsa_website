Breadth-First Search

Visit everything one step away, then everything two steps away — a queue makes "first seen, first visited" automatic.

Overview Breadth-First Depth-First Playground

The thought process

BFS answers "who's closest?" first. The trick is a queue: a first-in, first-out line. You add the start vertex, then repeatedly take the vertex at the front, visit it, and add any not-yet-seen neighbours to the back. Because neighbours added earlier come out earlier, you finish a whole "ring" of equal-distance vertices before touching the next ring.

  1. Put the start vertex in the queue and mark it seen.
  2. While the queue isn't empty, take the front vertex and visit it.
  3. For each neighbour that isn't seen yet, mark it seen and add it to the back of the queue.
Mark seen when you enqueue, not when you visit. If you wait until a vertex is dequeued to mark it, the same vertex can get added to the queue several times (by different neighbours) before it's ever visited — and you'd process it twice. Marking at enqueue time guarantees each vertex enters the queue exactly once.

Reading the code

The seen array is what stops BFS from looping forever on a graph with cycles — without it, two vertices pointing at each other would bounce back and forth. The while loop runs once per vertex (each is dequeued exactly once), and the inner for runs once per edge, so the whole traversal is O(V + E).

The payoff: on an unweighted graph, the order BFS first reaches each vertex is also the order of increasing distance from the start — so BFS hands you the shortest path in number of hops for free. Record each vertex's "who added me" and you can trace that path back.
