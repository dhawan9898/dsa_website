Dots And The Lines Between Them

Graph (BFS & DFS)

The most general structure of all — anything that's a set of things with connections. Two classic ways to explore one: breadth-first and depth-first.

Overview Breadth-First Depth-First Playground

The idea, in one picture

A graph is just things and the connections between them. The things are called vertices (or nodes); the connections are edges. That's the whole definition — and it's so general that almost everything is a graph: cities joined by roads, people joined by friendships, web pages joined by links, tasks joined by "must happen before" arrows.

A tree is actually just a special, tidy graph (one with no cycles and a single root). A graph drops those rules: any vertex can connect to any other, a connection can loop back, and there needn't be a "top".

Two flavours of edge. An edge can be undirected (a two-way street: if A connects to B, B connects to A — like a friendship) or directed (a one-way arrow: A→B doesn't imply B→A — like "follows" on social media). Edges can also carry a weight — a cost or distance — which is what Dijkstra's and MST algorithms care about. This page uses the simplest kind: undirected, unweighted.

How a computer stores one

the adjacency list

There's no "graph" keyword in C — you build one. The most common way is an adjacency list: for each vertex, keep a list of the vertices it's directly connected to. Vertex A's list is [B, D], vertex B's is [A, C, E], and so on. To ask "who can I reach in one step from here?" you just read that vertex's list. (The other common option is an adjacency matrix — a grid of 0/1 flags — better when the graph is dense.)

Exploring it: two orders

breadth-first spreads out; depth-first plunges in

Given a graph, the basic question is "starting here, which vertices can I reach, and in what order do I visit them?" There are two famous answers, and they differ only in which vertex you pick next:

  • Breadth-first (BFS) explores in rings: first everything one step away, then everything two steps away, and so on. It uses a queue (first-in, first-out).
  • Depth-first (DFS) plunges down one path as far as it can, then backtracks and tries the next. It uses a stack (or, equivalently, recursion).

Going deeper

costs and where graphs show up
OperationWhat it doesTime
BFS / DFSVisit every reachable vertex onceO(V + E)
Add edgeAppend to a vertex's adjacency listO(1)
Is A adjacent to B?Scan A's list (matrix: O(1))O(deg A)

V is the number of vertices, E the number of edges. Both traversals touch every vertex and every edge once, so both are O(V + E) — you can't do better if you must look at the whole graph.

Why the traversal order matters. On an unweighted graph, BFS finds the path with the fewest edges — the shortest route in "number of hops" — because it reaches every vertex by its nearest ring first. DFS doesn't promise that, but its plunge-and-backtrack shape is exactly what you want for detecting cycles, finding connected pieces, and ordering tasks by dependency.

Where you'll meet graphs. Maps and GPS routing, social networks, the web's link structure, build systems and package managers (dependency graphs), network packet routing, and state-space search in games and puzzles. Weighted, directed versions power shortest-path and minimum-spanning-tree algorithms.
