Vertices · Edges · Traversal

Graph

A set of vertices, connected by edges — the shape underneath maps, networks, dependencies, and relationships.

Notes

A graph is just vertices (the dots) and edges (the connections between them). That's a deliberately loose definition — trees, linked lists, and grids are all special-case graphs. Edges can be directed (one-way, like a "follows" relationship) or undirected (two-way, like a "friends with" relationship, the kind used on this page), and can carry weights (like distance or cost) or not.

The two fundamental ways to explore a graph from a starting vertex are breadth-first search (BFS) and depth-first search (DFS). Both visit every reachable vertex exactly once, in O(V + E) time — the difference is purely the order:

  • BFS uses a queue: visit the start, then all its neighbours, then all of their unvisited neighbours, spreading outward one full "ring" at a time. In an unweighted graph, this is also how you find the shortest path.
  • DFS uses a stack (or recursion): commit to one neighbour, then one of its neighbours, as deep as possible, only backtracking when it hits a dead end.
OperationTime
Add vertexO(1)
Add / remove edgeO(1)
BFS / DFS (whole graph)O(V + E)

This is the model behind road-network routing, social-network "friends of friends," dependency graphs (build systems, package managers), and the web itself — pages as vertices, links as edges.

Implementation: the code panel below stores each vertex's neighbors as its own small array — g->adj[v] — alongside a count, g->deg[v], of how many it currently has. Adding an edge is just appending to two arrays at once, one per endpoint, which is exactly why it's O(1). BFS and DFS both boil down to "visit a vertex, then walk g->adj[cur] and recurse or enqueue whatever isn't visited yet" — the only real difference between them is which data structure holds the not-yet-visited vertices: BFS uses an explicit queue, DFS uses the call stack (recursion) as an implicit one.

When it breaks: add an edge to only one endpoint's array and forget the other, and the graph quietly becomes directed without anyone deciding that on purpose — traversing from one side finds the neighbor, but traversing from the other side never finds the way back. The other classic bug is the visited check itself: skip it, or set it after the recursive call instead of before, and a single cycle turns BFS or DFS into an infinite loop, since there's nothing left to stop it from walking back around forever.
