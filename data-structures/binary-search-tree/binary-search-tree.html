Left Is Smaller · Right Is Larger

Binary Search Tree

A tree shaped so every node's left subtree is entirely smaller than it, and its right subtree entirely larger.

Notes

A binary search tree (BST) is defined by one invariant, applied at every node: everything in its left subtree is smaller, everything in its right subtree is larger. That's it — but it's enough to turn search into the same halving trick as binary search on a sorted array, except the "halving" is baked into the tree's shape instead of computed with a midpoint each time.

Insert and delete follow the exact same left/right comparisons down from the root that search does. Delete is the one tricky case: removing a node with two children would leave a hole with two dangling subtrees, so its value gets replaced by its in-order successor (the smallest value in its right subtree) instead, which is always safe to move up.

OperationWhat it doesTime (balanced)Time (worst case)
SearchCompare and go left or rightO(log n)O(n)
InsertWalk to an empty spot, place it thereO(log n)O(n)
DeleteFind it, then splice or replace with successorO(log n)O(n)
In-order traversalVisit left, self, right — yields sorted orderO(n)

The worst case happens when insertions arrive in already-sorted order, degenerating the tree into a straight line — no better than a linked list. Self-balancing variants like the AVL Tree exist specifically to rule that out.
