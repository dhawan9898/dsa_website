Smaller Left, Bigger Right

Binary Search Tree

A tree that keeps its keys sorted by one simple rule, so you can find, add, or remove any key by following a single path down.

Overview Insert & Search Delete Playground

The idea, in one picture

A tree is nodes connected like a family tree: one node at the top (the root), each node with up to two children below it — a left child and a right child. "Binary" just means "at most two children." A binary search tree adds one rule that makes it powerful:

The BST rule. For every node, all keys in its left subtree are smaller, and all keys in its right subtree are bigger. That single invariant holds everywhere in the tree, at every node — which means the keys are, in a sense, already sorted by position.

Why care? Because that rule turns searching into a series of yes/no turns. Looking for a key, you stand at the root and ask "is my key smaller or bigger?" — smaller, go left; bigger, go right. Each step throws away a whole subtree you don't need to look at, the same halving trick as binary search, but built into a structure you can also cheaply insert into and delete from. Going deeper

why balance is everything
OperationBalancedWorst case (lopsided)
SearchO(log n)O(n)
InsertO(log n)O(n)
DeleteO(log n)O(n)

Every operation walks one path from the root to somewhere below, so its cost is the tree's height, h. A nicely balanced tree of n nodes has height about log₂ n (7 nodes → height 3), so everything is O(log n) — wonderfully fast.

The catch: order of insertion. Insert keys already in sorted order (1, 2, 3, 4, …) and every new key goes to the right, so the "tree" degenerates into a straight line — a linked list in disguise, with height n and O(n) operations. A BST is only as good as it is balanced.

That fragility is exactly why self-balancing trees exist: the AVL tree and red-black trees do a little extra rearranging on every insert and delete to guarantee the height stays ~log n no matter what order the keys arrive in. A plain BST is the foundation; those are the hardened versions built on top of it.

Where you'll meet BSTs. Ordered maps and sets (C++ std::map, Java TreeMap), database indexes, anything that needs keys kept in sorted order and fast insert/delete — a hash table is faster for pure lookup, but a BST also gives you "next bigger key," "everything in a range," and sorted iteration for free.
