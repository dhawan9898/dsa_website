One Walk, Two Uses

Insert & Search

Both operations are the same left/right walk down from the root — they just stop at different moments.

Overview Insert & Search Delete Playground

Search: follow the comparisons down

O(h)

To find a key, start at the root and at each node make one comparison: equal means you found it; smaller means the key can only be in the left subtree; bigger means the right. Each step drops a whole subtree, so you reach the answer (or fall off to NULL) in at most h steps.

  1. Start cur at the root.
  2. Compare: == → found. < → go left. > → go right.
  3. Fell off to NULL → the key isn't in the tree.

 

Insert: walk to an empty spot, hang a leaf

O(h)

Insert uses the identical walk — but instead of stopping on a match, it keeps going until the branch it wants is empty, and attaches the new key there as a leaf. A brand-new key always becomes a leaf; it never displaces an existing node.

  1. Walk down comparing, remembering the parent as you go.
  2. When the next step would go to a NULL child, stop — that empty spot is where the key belongs.
  3. Create the node and link it as the parent's left or right child.

 

The BST rule stays true automatically. Because you only ever turn left for smaller and right for bigger, the new leaf lands exactly where the ordering says it must — no re-sorting needed.
