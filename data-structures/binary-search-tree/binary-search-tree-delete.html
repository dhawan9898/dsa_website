The three cases

First you find the node exactly like a search. Then how you remove it depends on how many children it has:

  1. No children (a leaf). Just detach it from its parent — done.
  2. One child. Splice it out: point its parent straight at its single child, the same move as a linked-list delete.
  3. Two children. The hard case — you can't just remove it without orphaning two subtrees. The trick below handles it.
The two-children trick: the in-order successor. The successor is the next-largest key — the smallest key in the node's right subtree (go right once, then left as far as you can). Copy that value up into the node you're deleting, then delete the successor from its old spot. The successor has no left child (it was the leftmost), so removing it is always the easy case 1 or 2. The tree stays perfectly sorted because the successor was, by definition, the closest key allowed to sit there.
