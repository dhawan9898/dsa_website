Disjoint Sets · Find · Union

Union‑Find

Tracks a collection of disjoint sets and answers "are these two elements in the same set?" in almost constant time.

Notes

Union-Find (also called Disjoint Set Union, or DSU) tracks a collection of non-overlapping sets and supports two operations: find(x) — which set is x in? — and union(a, b) — merge a's set and b's set into one. Every set is stored as a little tree: each element has a single parent pointer, and the root of a tree (the element that is its own parent) names the whole set. Two elements are in the same set exactly when walking their parent pointers reaches the same root.

OperationWhat it doesTime
FindWalk parent pointers up to the rootO(α(n)) amortized
UnionFind both roots, attach one under the otherO(α(n)) amortized

Implementation: two optimizations turn a naive O(n)-per-operation structure into one that's effectively O(1). Union by rank always attaches the shallower tree under the deeper one instead of picking arbitrarily, which caps every tree's height at O(log n). Path compression — the recursive line parent[x] = find(parent, parent[x]) below — rewires every node visited during a find directly to the root, so the *next* find along that path is a single hop. Together they give the inverse Ackermann bound, α(n), which never exceeds 4 for any n that fits in memory.

Common mistake: implementing union without ever checking whether a and b are already in the same set — calling union on two elements that already share a root should be a no-op, but skipping that check and blindly attaching find(a) under find(b) anyway creates a self-referencing cycle (a root pointing at itself through another node), corrupting the whole structure.

This is the standard engine behind cycle detection while building a graph edge by edge (exactly what Kruskal's MST uses it for), network connectivity queries, and finding connected components in an image.
