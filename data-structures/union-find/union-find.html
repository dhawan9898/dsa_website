Which Group Am I In?

Union‑Find

A tiny structure that tracks "who is grouped with whom" and merges groups — almost instantly, no matter how many merges you do.

Overview Find & Union Playground

The idea, in one picture

Picture a bunch of islands. Every so often someone builds a bridge between two of them, and you keep being asked one question: "can I already get from this island to that one?" — that is, are they in the same connected group yet? Union-Find (also called a disjoint-set structure) answers exactly that, and supports exactly two moves:

  • Find(x) — which group is x in? It returns the group's representative: one member chosen to stand for the whole group.
  • Union(x, y) — merge x's group and y's group into one.

Two elements are in the same group exactly when Find(x) == Find(y) — they report the same representative.

The representation. Each element stores just one thing: a parent. Follow parents upward and you eventually reach an element that is its own parent — that's the root, the group's representative. So each group is an up-tree, and the whole structure is a forest of them. It's all held in one array: parent[i].

Going deeper

the two tricks, and where it's used

Done naively, trees can grow tall and thin — a find then walks a long chain, O(n). Two small optimizations flatten them so both operations become almost O(1):

TrickWhat it does
Union by size/rankAlways hang the smaller tree under the bigger root, so height barely grows.
Path compressionAfter a find, re-point every node on the path straight at the root, so next time is instant.

With both, m operations on n elements run in O(m · α(n)), where α is the inverse Ackermann function — below 5 for any number of elements you could ever store. Effectively constant time per operation.

Why not just a "group id" per element? That makes find O(1) but union O(n) — you'd have to relabel every member of one group. Union-Find flips that: it keeps both operations cheap by never relabelling, just re-pointing a single root.

Where you'll meet it. Kruskal's MST uses it to reject edges that would form a cycle (both endpoints already in one group); network/percolation connectivity; image segmentation (merging pixel regions); detecting cycles in an undirected graph; and "friend circles" or account de-duplication.
