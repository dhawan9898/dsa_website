Smallest Always On Top

Priority Queue (Heap)

A queue where items leave in priority order, not arrival order — built on a clever array-as-tree called a binary heap.

Overview Insert & Extract Playground

The idea, in one picture

A hospital emergency room doesn't treat people first-come-first-served — the most urgent case goes next, no matter when they arrived. A priority queue is that rule as a data structure: you add items with a priority, and each time you remove one you get the highest-priority item currently waiting. (A plain queue is the special case where priority = arrival time.)

The catch is doing both operations — add anything and always remove the best — fast. A sorted list makes remove-best O(1) but insert O(n); an unsorted list makes insert O(1) but remove-best O(n). The binary heap is the elegant compromise: both are O(log n).

The heap property. A heap is a complete binary tree (every level full, last level filled left-to-right) with one rule: every parent is ≤ both of its children (a min-heap). That rule, applied everywhere, forces the smallest value to sit at the root — so "find the minimum" is instant, O(1). (Flip the comparison for a max-heap, where the largest is on top.)

The trick: a tree with no pointers

the heap lives in a flat array

Here's the neat part: because a heap is always a complete tree, you don't need any pointers to store it — a plain array is enough. Lay the nodes out top-to-bottom, left-to-right, and the tree shape is implied by arithmetic:

the node at index i has its children at 2i+1 and 2i+2, and its parent at (i−1)/2.

Build heapHeapify an existing arrayO(n)

Insert and extract each touch a single root-to-leaf path — the height, log n — because the tree is always complete and so perfectly balanced by construction (no rotations needed, unlike an AVL tree).

A heap is not sorted. It only promises the minimum is on top — the rest is loosely ordered. That's exactly enough for "always give me the smallest," and no more, which is why it's so cheap.

Where you'll meet heaps. Dijkstra's shortest-path and Prim's/Kruskal's MST use one to always expand the cheapest edge next; OS and event schedulers use one to run the highest-priority task; heap sort is literally "insert everything, then extract-min repeatedly"; and "top-K" queries keep a heap of the K best seen so far.
