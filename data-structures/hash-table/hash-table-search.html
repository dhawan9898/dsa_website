One Bucket, One Short Chain

Search & Delete

Both start the same way: hash the key to its bucket, then work only within that bucket's chain.

Overview Insert Search & Delete Playground

Search: hash, then walk one chain

O(1) average

To find a key, hash it to a bucket with the same key % M used on insert, then walk just that bucket's chain comparing keys. You never touch the other buckets — that's the whole speed idea.

  1. i = key % M — jump straight to the bucket.
  2. Walk that bucket's chain (cur = cur->next), comparing each key.
  3. Match → return it. Reached NULL → it's not in the table.

 

Why it's O(1) on average. With a good hash and a sensible load factor, each chain holds only a handful of keys, so the walk is over almost instantly. Only if a bucket becomes badly overloaded does search creep toward O(n).

Delete: find it, then unlink it

O(1) average

Delete is search plus a linked-list removal. Once the walk finds the key, unlink its node from the chain exactly as you would in a linked list — the predecessor's next skips over it (or the bucket points past it, if it was the chain head) — then free it.
