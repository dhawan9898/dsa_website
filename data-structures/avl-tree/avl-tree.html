Self-Balancing · Never O(n)

AVL Tree

A binary search tree that rebalances itself after every insert and delete, so it can never degrade into a straight line.

Notes

A plain binary search tree can degrade into something no better than a linked list — insert values in sorted order and every new node just becomes the previous one's only child. An AVL tree rules that out with one extra rule on top of the BST invariant: for every node, the height of its left and right subtrees can differ by at most 1 — its balance factor.

After every insert or delete, the tree walks back up from the changed node to the root, checking the balance factor at each ancestor. The moment one strays outside [-1, +1], a rotation fixes it — one of four shapes, depending on which side is heavy and which side of that child is heavy:

  • Left-Left — a single right rotation
  • Right-Right — a single left rotation
  • Left-Right — rotate the left child left, then rotate the node right
  • Right-Left — rotate the right child right, then rotate the node left
OperationTime (guaranteed)
SearchO(log n)
InsertO(log n)
DeleteO(log n)

The guarantee — never worse than O(log n), no matter the insertion order — is what makes AVL trees (and relatives like red-black trees) the backbone of ordered sets/maps in standard libraries and database indexes.

Implementation: the code panel below writes insert and delete recursively — unlike the plain BST's iterative walk, AVL needs the call stack: rebalancing happens on the way back up from wherever the tree actually changed, one ancestor at a time, and recursion is what gives you that unwind for free.

When it breaks: update a node's height before its children have finished rebalancing (or skip the update entirely) and every balance-factor check above it works from stale data — either missing a real imbalance or rotating when nothing was actually wrong. The other classic mistake is stopping at the first rotation instead of continuing the unwind: fixing the nearest unbalanced node doesn't guarantee an ancestor further up is still within [-1, +1].
