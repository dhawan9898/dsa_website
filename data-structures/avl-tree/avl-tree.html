A BST That Rebalances Itself

AVL Tree

A binary search tree that does a little rearranging on every change so it can never grow lopsided — keeping every operation O(log n).

Overview Rotations Playground

The problem it fixes

Read the binary search tree first. A BST is fast only when it's balanced — its speed is its height. Insert keys in sorted order (10, 20, 30, 40 …) and every key goes right, so the tree degenerates into a straight line of height n, and searches crawl at O(n). A plain BST has no defense against that.

An AVL tree (named after inventors Adelson-Velsky and Landis) is a BST that refuses to get lopsided. After every insert or delete it checks whether any node has become too unbalanced and, if so, performs a quick local rearrangement — a rotation — to fix it. The result: the height is guaranteed to stay ≈ log n no matter what order keys arrive in, so search / insert / delete are all O(log n), always.

The balance factor. For each node, the balance factor is the height of its left subtree minus the height of its right. AVL's rule: this must always be -1, 0, or +1. The moment an insert or delete pushes some node to +2 (too left-heavy) or -2 (too right-heavy), a rotation snaps it back into range.

What a rotation looks like

insert 10, 20, 30 — the third would make a line, so the tree pivots

Inserting 10, then 20, then 30 into a plain BST makes the chain 10 → 20 → 30. AVL spots that node 10 is now right-heavy by 2 and rotates it left: 20 rises to become the root, 10 becomes its left child, 30 its right. Going deeper

the cost of staying balanced
OperationPlain BST (worst)AVL (guaranteed)
SearchO(n)O(log n)
InsertO(n)O(log n)
DeleteO(n)O(log n)

Insert and delete still walk one path down (O(log n)); the only extra work is, on the way back up, checking each node's balance and doing at most one rotation, each of which is a constant number of pointer swaps — O(1). So the guarantee is essentially free.

AVL vs. red-black. AVL trees keep balance tighter than red-black trees, so lookups are a touch faster, but they rotate a little more often on inserts/deletes. Red-black trees relax the balance rule slightly for fewer rotations — which is why libraries (Java TreeMap, C++ std::map, the Linux kernel) tend to use red-black. AVL is the cleaner one to learn the self-balancing idea from, and the winner when reads vastly outnumber writes.
