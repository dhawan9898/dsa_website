Each Node Points To The Next

Singly Linked List

A chain of nodes, each holding a value and a pointer to the next one — or NULL if it's the last.

Notes

An array stores its elements in one contiguous block of memory, so inserting in the middle means shifting everything after it. A linked list gives up that contiguity: every node is its own small object, wherever it happens to live in memory, holding a value and a pointer to the next node. Insertion and deletion become a matter of rewiring a couple of pointers — no shifting at all — but you lose O(1) random access: to reach node k you must walk k pointers from the head, one at a time.

Implementation: every node is a tiny two-field struct — a value and a next pointer to the following node (NULL for the last one). The list itself is just a single head pointer into this chain; there's no fixed size and no capacity to run out of. Creating a node means allocating it on the heap (see the code panel below) — unlike the array-backed Stack, which reserves all its memory up front, a linked list grows one allocation at a time, exactly when it needs to.

When it breaks: mis-ordering the pointer rewiring is the classic bug — set head to the new node before saving its next link to the old head, and you silently orphan the rest of the list (nothing points to it anymore, but it's still sitting in memory — a leak). Delete a node without freeing it and you leak that memory too; keep using a pointer after freeing it and you get a dangling-pointer bug, reading or writing memory that's no longer yours. None of these crash predictably — they're the kind of bug that only shows up as corruption somewhere else, later.
