Each Node Points To The Next

Singly Linked List

A chain of nodes, each holding a value and a pointer to the next one — or NULL if it's the last.

Notes

Start with a picture. Imagine a scavenger hunt. You're handed one clue; it doesn't hold the prize, it holds the location of the next clue. That clue points to another, and so on, until a clue says "this is the last one." A linked list is exactly that: a chain of nodes, where each node holds a value plus a pointer — the address of the next node. The very first clue is the head. The last node points at NULL, the "there is nothing after me" marker.

Why not just use an array? An array keeps its items shoulder to shoulder in one solid block of memory. That makes jumping to item #500 instant — but inserting into the middle means physically shoving everything after it over to make room, which gets slower the bigger the array is. A linked list makes the opposite trade: its nodes are scattered anywhere in memory, connected only by those "next" pointers, so inserting or deleting is just re-clipping a pointer or two — no shifting, ever. The price you pay is that reaching node #500 means following 500 pointers from the head, one hop at a time; there's no jumping. (If "pointer" is a fuzzy word, the Pointers page explains it from scratch.)

What a node actually is. In C, each node is a tiny two-field bundle: a value and a next pointer to the following node (NULL for the last one). The list itself is nothing but a single head pointer into this chain. There's no fixed size and no capacity to run out of — unlike the array-backed Stack, which reserves all its memory up front, a linked list grows one node at a time, exactly when it needs to.

Every operation you can do to a linked list is built from one humble move — walking the chain from the head — and the four operations below are just "walk to the right spot, then rewire." Each has its own page that builds the idea from zero, with a step-by-step animation and the C code line by line.

Used wherever insertions and deletions dominate over random lookups: implementing stacks and queues, adjacency lists for graphs, and the underlying node chain inside a hash table's chaining buckets (see the Hash Table page).
