Each Node Points Both Ways

Doubly Linked List

A linked list with a second pointer in every node — one to the next node and one to the previous — so you can walk it in either direction.

Overview Insertion Deletion Traversal Playground

The idea, in one picture

Read the singly linked list first — a doubly linked list (DLL) is that, with one addition. In a singly list each node knows only the node after it, so you can only ever move forward, and you can never look back. A DLL gives every node a second pointer, prev, aimed at the node before it. Now the chain is a two-way street: from any node you can step forward with next or backward with prev.

Think of train cars coupled at both ends instead of one. The list keeps a HEAD (first car) and usually a TAIL (last car); the head's prev is NULL and the tail's next is NULL, marking the two ends.

One extra pointer, three payoffs. A DLL can (1) walk backward as easily as forward, (2) insert at the tail in O(1) using the tail pointer, and (3) delete a node you're already standing on in O(1) — because that node's prev and next hand you both neighbours instantly, with no walk to find "the node before." The cost is one more pointer of memory per node, and one more link to keep correct on every insert and delete.

Going deeper

costs, trade-offs, and where DLLs show up
OperationSinglyDoubly
Insert / delete at headO(1)O(1)
Insert / delete at tailO(n) (walk to find it)O(1) (tail pointer)

The trade-off. Every benefit above comes from the extra prev pointer — which means more memory per node and a second link to update on every structural change. Get one of the two links wrong (a classic bug is fixing next but forgetting prev) and the list is corrupt in one direction only, which is nastily hard to spot.

Where you'll meet DLLs. Browser history (back and forward), the undo/redo timeline in editors, LRU caches (move a used item to the front, evict from the back — both O(1)), music/media playlists with previous-track, and the standard-library list / LinkedList in most languages. A deque is often a DLL under the hood.
