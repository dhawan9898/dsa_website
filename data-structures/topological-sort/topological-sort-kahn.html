Count, Queue, Peel, Repeat

Kahn's Algorithm

A tidy BFS-shaped sort: keep an in-degree count per vertex, and always output whatever is left with nothing pointing at it.

Overview Kahn's Algorithm Playground

The thought process

Kahn's algorithm is BFS with a twist: instead of a "seen" flag, each vertex tracks its in-degree — the number of unmet prerequisites. A vertex is allowed into the output only once that count reaches 0.

  1. Count in-degrees: walk every edge and add 1 to the vertex it points at.
  2. Queue every vertex whose in-degree is already 0 — these depend on nothing.
  3. Peel: dequeue a vertex, output it, and for each vertex it points at, subtract 1. Any that hit 0 are now ready — enqueue them.
  4. Repeat until the queue empties. If you output fewer than V vertices, the leftovers form a cycle.
Why --indeg[v] instead of re-counting? Outputting u "satisfies" exactly one prerequisite for each vertex u points at. Decrementing is that satisfaction in one step — no need to rescan. When a vertex's count reaches 0, every prerequisite is met and it's safe to place.

Reading the code

Counting in-degrees scans every edge once (O(E)); finding the initial ready vertices scans every vertex once (O(V)); then the main loop dequeues each vertex once and decrements along each edge once more. Total: O(V + E) — the same linear cost as BFS, which is exactly what this is.

The final if (count < V) is the cycle check. Vertices trapped in a cycle keep pointing at each other, so their in-degrees never reach 0, they never enter the queue, and count falls short. No extra work — the shortfall itself is the proof.
