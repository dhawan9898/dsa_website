Topological Sort

Orders the vertices of a directed graph so every edge points from earlier to later in the order.

Notes

A topological sort takes a directed graph and lines up its vertices so that every edge points "forward" — if there's an edge u→v, then u comes before v in the order. Think of edges as "must happen before": course prerequisites, build-system dependencies, spreadsheet formula recalculation order. A topological order only exists at all when the graph has no cycle — a DAG, directed acyclic graph — since a cycle means each vertex in it depends on another that depends back on it, with no valid "first."

Kahn's algorithm (shown here) finds one: track every vertex's in-degree (how many edges point at it — how many prerequisites it has left), start with every vertex that already has zero, and repeatedly peel one off, decrementing its neighbors' in-degrees. A neighbor whose in-degree just hit zero has had its last prerequisite satisfied, so it joins the queue too.

Implementation: the code panel below is exactly BFS with a different starting condition — instead of starting from one chosen source, it starts from every vertex that has no prerequisites at all, and "visiting" a vertex means decrementing its neighbors' in-degrees rather than just marking them seen. That structural similarity isn't a coincidence: both are "process ready work, discover more ready work" algorithms.

Common mistake: forgetting to check whether every vertex actually made it into the order. If the graph has a cycle, every vertex in that cycle keeps at least one unsatisfied prerequisite forever, so the queue runs dry with vertices left over — comparing the final order's length against the vertex count is the standard, cheap way to detect that and report "no valid order exists" instead of silently returning a partial, wrong answer.
