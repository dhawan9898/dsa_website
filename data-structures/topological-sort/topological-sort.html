An Order That Respects Every “Must Come First”

Topological Sort

Given tasks with "this before that" dependencies, line them all up so every task comes after the ones it depends on.

Overview Kahn's Algorithm Playground

The idea, in one picture

To get dressed you put socks on before shoes, and a shirt before a jacket — but socks and shirt have no order between them. Course prerequisites, build steps, spreadsheet cell formulas, package installs: all the same shape — a set of tasks where some must happen before others, and the rest are free.

A topological sort takes that tangle of "before" arrows and flattens it into a single line where every arrow points forward — no task ever appears before something it depends on. There can be many valid orders (socks-then-shirt or shirt-then-socks both work); topological sort finds one of them.

It only works on a DAG. The graph must be directed (arrows have a direction: "A before B") and acyclic (no cycles). If A needs B, B needs C, and C needs A, there's no valid order at all — that's a contradiction, and a good topological-sort algorithm detects it rather than looping forever.

The trick: in-degree

a task is ready when nothing points at it

The cleanest method (Kahn's algorithm) rests on one number per vertex: its in-degree — how many arrows point into it, i.e. how many unfinished prerequisites it still has. A vertex with in-degree 0 depends on nothing, so it's ready and safe to output next. Output it, then "remove" its outgoing arrows — which lowers its dependents' in-degrees. Some of them now hit 0 and become ready in turn.

Cycle detection comes free. If the graph has a cycle, the vertices in that cycle can never reach in-degree 0 (they forever point at each other), so the queue empties while some vertices are still unplaced. Output fewer than V vertices ⟹ there's a cycle. That's often why you run a topological sort — to check a dependency graph is even satisfiable.

Where you'll meet it. Build systems and make (compile in dependency order), package managers resolving install order, task schedulers, spreadsheet recalculation, course-prerequisite planning, and detecting circular dependencies (the DFS version of topo-sort is a cornerstone of that). It's really just a specialized graph traversal — a directed cousin of BFS.
