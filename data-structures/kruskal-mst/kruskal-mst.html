Minimum Spanning Tree · Cheapest Edges First

Kruskal’s MST

Finds the cheapest possible set of edges that connects every vertex in a weighted graph, with no cycles.

Notes

A minimum spanning tree (MST) is the cheapest possible subset of a connected, undirected, weighted graph's edges that still connects every vertex — always exactly V−1 edges for V vertices, and no cycles (a cycle would mean some edge in it could be removed for free). Kruskal's algorithm builds one greedily: sort every edge by weight, then walk the sorted list accepting an edge whenever its two endpoints aren't already connected, and skipping it when they are — accepting it would only close a cycle, never help connect anything new.

"Are these two vertices already connected?" is exactly the question Union-Find answers in almost constant time: two vertices are connected exactly when find returns the same root for both. That's why Kruskal's and Union-Find are taught together — the graph algorithm's core decision is a disjoint-set query.

StepCost
Sort E edgesO(E log E)
E finds + up to V−1 unionsO(E · α(V)), effectively O(E)
TotalO(E log E) — dominated by the sort

Implementation: the code panel below stops the loop the instant count reaches n - 1 — a spanning tree on n vertices needs exactly that many edges and never more, so once it's found there's no reason to keep scanning the (possibly much longer) sorted list.

Common mistake: checking whether an edge's endpoints are equal by comparing the vertices themselves instead of their roots — edges[i].from == edges[i].to only catches a self-loop, not the far more common case of two different vertices that are already connected through some other path. Cycle detection has to go through find, not a direct comparison.
