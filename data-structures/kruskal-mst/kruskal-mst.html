Connect Everything For The Least Total Cost

Kruskal’s MST

Pick the cheapest edges that connect every vertex without ever forming a loop — the minimum spanning tree.

Overview Building the MST Playground

The idea, in one picture

You have towns and the costs to lay cable between some of them. You want every town connected — power can flow from any town to any other — for the least total cable. You'd never pay for a loop (if a town is already reachable, a second path is wasted money), and you need exactly enough links to tie everyone together. That cheapest loop-free connector is a minimum spanning tree (MST).

A spanning tree of a graph is a subset of edges that touches every vertex (spans them) and has no cycle — which for V vertices means exactly V−1 edges. The minimum spanning tree is the spanning tree whose edge weights add up to the smallest total.

Kruskal's greedy rule. Sort every edge cheapest-first, then walk the list once: take an edge if it joins two so-far-separate pieces, and skip it if both its endpoints are already connected (taking it would make a cycle). Stop once you've taken V−1 edges. That's the whole algorithm.

The engine underneath: Union-Find

how "are these already connected?" stays cheap

The one hard part is the test "are these two endpoints already connected?" Checking by searching the graph each time would be slow. Instead Kruskal leans on Union-Find: each vertex starts in its own group, find tells you an edge's two endpoints' groups, and if they differ you union them as you take the edge. Same group ⟹ taking the edge would close a loop ⟹ skip it.

Why greedy works here. The cheapest edge crossing between any two groups is always safe to include in some MST (the "cut property"). Kruskal takes edges in global cheapest-first order, and each one it keeps is exactly such a safe edge — so the greedy choice never has to be undone.

Kruskal vs Prim. Both build an MST greedily. Kruskal sorts all edges and grows a forest that merges into one tree (great when edges are few, or already sorted). Prim grows one tree outward from a start vertex using a heap, like Dijkstra (great when edges are dense).

Where you'll meet it. Network and utility layout (cable, pipes, roads for least cost), clustering (cut the most expensive MST edges to split data into groups), and approximate solutions to harder routing problems.
