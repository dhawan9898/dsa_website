Sort Once, Take Or Skip

Building the MST

Walk the sorted edge list once. Each edge is either a new connection to keep or a cycle to skip — and union-find tells you which.

Overview Building the MST Playground

The thought process

Everything hinges on processing edges in the right order and using union-find to keep the "already connected?" test cheap:

  1. Sort all edges by weight, cheapest first.
  2. Put every vertex in its own group (makeset).
  3. For each edge in order: if its endpoints have different roots, take it and union them; if the same root, skip it (a cycle).
  4. Stop as soon as you've taken V−1 edges — the tree is complete.
Why cheapest-first is safe. When you take an edge, it's the cheapest one that still joins two separate pieces — and the cut property guarantees such an edge belongs to some MST. So no choice ever needs to be undone; greedy is optimal here.

Reading the code

The sort dominates the running time at O(E log E); everything after it is E iterations, each doing two finds and maybe a union — effectively constant thanks to union-find's α(V). So the whole algorithm is O(E log E). If the edges arrive already sorted, it's essentially linear.

if (ra == rb) continue; is the entire cycle check — no graph search, just comparing two roots. And if (taken == V-1) break; lets it stop early, the moment the tree spans every vertex, rather than scanning the remaining (more expensive) edges.
