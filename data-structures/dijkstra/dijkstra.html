Shortest Paths · Weighted · Directed

Dijkstra’s Algorithm

Finds the shortest distance from one starting vertex to every other vertex in a weighted graph with no negative edges.

Notes

Dijkstra's algorithm finds the shortest path from a single source to every other vertex in a weighted graph. It's greedy: keep a running "best known distance" for every vertex (0 for the source, infinity for everyone else), and repeatedly settle the closest unvisited vertex — once a vertex is settled, its distance is final and never changes again. Settling a vertex relaxes every edge leaving it: if going through the just-settled vertex would beat a neighbor's current best distance, that neighbor's distance improves.

VersionTime
Linear scan for the minimum (shown here)O(V²)
Binary heap priority queueO((V + E) log V)

Implementation: the code panel below picks the next vertex to settle with a plain linear scan over every unvisited vertex — simple, and fine for the small graphs here, but it's the O(V²) part. Swapping that scan for a binary heap (always pull the minimum-distance vertex in O(log V) instead of scanning for it) is the standard optimization, and it's the exact same heap already covered on this site — Dijkstra is one of the two textbook reasons a priority queue exists in the first place.

Common mistake: Dijkstra's greedy guarantee — once settled, a distance is final — only holds because edge weights are non-negative. With a negative edge, a path discovered after a vertex is settled could still be shorter, but the algorithm never looks back to check. Running it unmodified on a graph with negative weights doesn't crash — it just silently returns wrong distances. (Bellman-Ford is the standard fix when negative edges are possible.)
