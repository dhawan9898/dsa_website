Extract-Min, Relax, Repeat

Shortest Path

The whole algorithm is a loop: take the cheapest un-finalized vertex, use it to relax its edges, and repeat until the heap is empty.

Overview Shortest Path Playground

The thought process

Keep a dist[] table — the best cost found so far to each vertex — and a min-heap of vertices keyed by that cost. Start with dist[source] = 0 and everything else ∞. Then repeat one confident move:

  1. Extract-min: pull the vertex with the smallest dist out of the heap — its cost is now final (nothing can beat it).
  2. Relax each of its edges: if reaching a neighbour through this vertex is cheaper than the neighbour's current dist, lower it and push the neighbour back on the heap.
  3. Repeat until the heap is empty. Every vertex gets finalized exactly once.
Why if (done[u]) continue;? Relaxing can push the same vertex onto the heap several times at different costs. When you extract it, the first (cheapest) copy is the real one; any later, staler copies are skipped with this check. It's simpler than deleting old heap entries and just as correct.

Reading the code

Every vertex is extracted from the heap once (O(V) extractions, each O(log V)), and every edge triggers at most one relaxation that pushes to the heap (O(E) pushes, each O(log V)). Together that's O((V + E) log V) — near-linear, and the reason Dijkstra scales to real road networks.

To recover the actual path (not just its cost), store a prev[v] each time you relax: "the best way into v currently comes from u." When you're done, follow prev back from any vertex to the source.
