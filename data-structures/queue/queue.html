First In · First Out

Queue

A collection where you add at one end (the rear) and remove from the other (the front).

Notes

A queue models a line of people: new arrivals join at the rear, and whoever has been waiting longest leaves from the front. That's First In, First Out (FIFO) — the mirror image of a stack's LIFO rule.

Like a stack, every operation touches only one end, so enqueue and dequeue are both O(1) — if the underlying structure is chosen correctly. A naive array that physically shifts every remaining element down after each dequeue is O(n), not O(1); that shift is exactly what you're paying for if you reach for the wrong tool.

Implementation: the code panel below uses a linked list with two pointers, front and rear — unlike a plain linked list, which only ever tracks the head. Enqueue allocates a node and attaches it after rear; dequeue detaches front and advances it. Neither one ever walks the list, so both stay O(1) no matter how long the queue gets. (The visualization above shows the queue as a simple ordered row, front to rear — that's the abstract shape; Circular Queue shows the array-based alternative in full.)

When it breaks: dequeuing an empty queue means dereferencing a NULL front — an immediate crash, not silent corruption, which at least makes it easy to spot. The sneakier bug is forgetting to null out rear when the last node is removed: the next enqueue then attaches a new node onto a dangling rear pointer instead of correctly starting a fresh list.

Used anywhere work needs to be handled in arrival order: print spoolers, task/job schedulers, message queues between services, and breadth-first search (which explores nodes in the order it discovers them).
