Pop & Peek

Pop removes the top value and hands it back; peek shows it to you without touching the stack at all.

Overview Push Pop & Peek Playground

Pop: remove the top

O(1)

Popping takes the value currently on top, removes it from the stack, and returns it to the caller. Like push, it only ever touches the top, so it's the mirror image: instead of moving top up and writing, you read and move top down.

  1. Check it isn't empty. If top is -1, there's nothing to remove — stop (see underflow below).
  2. Read the top value at items[top] so you can return it.
  3. Move top down. top-- drops the index by one. The old value is still physically in the array, but top no longer counts it, so it's logically gone.

 

When it breaks: stack underflow. Popping (or peeking) an empty stack means reading items[-1] — off the front of the array. The if (top == -1) guard is what turns that from a memory bug into a clean "nothing to do."

Peek: look without removing

O(1)

Sometimes you want to see the top value but leave the stack exactly as it is — for example, to check what you'd get before deciding whether to pop it. That's peek (also called "top"). It's pop without the second half: read items[top] and return it, but leave top untouched.

 

Because nothing changes, peek is safe to call as often as you like — the only failure case is peeking an empty stack, guarded the same way as pop.
