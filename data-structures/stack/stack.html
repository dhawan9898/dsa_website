Last In · First Out

Stack

A pile where you can only ever touch the top: add on top, take from the top. That single rule is the whole data structure.

Overview Push Pop & Peek Playground

The idea, in one picture

Think of a stack of plates. You add a clean plate on top, and when you need one you take it from the top. You never pull a plate from the middle of the pile, and you never slide one in at the bottom — the top is the only end you touch. A stack the data structure is exactly this: a collection where every add and every remove happens at one end.

That one rule has a name: Last In, First Out, or LIFO. The last plate you put on is the first one you take off. Whatever went in most recently comes out first; the oldest thing sits at the bottom, waiting until everything above it is gone.

Three moves. Push = put a new value on top. Pop = take the top value off (and return it). Peek = look at the top value without removing it. That's the whole vocabulary — and each one gets its own page below, built up from zero with an animation and the C code.

How it works

an array + one index called top

The simplest way to build a stack is the one in the playground: take a plain array of a fixed size and keep a single integer called top that remembers the index of the highest occupied slot. When the stack is empty, top is -1 (a "points at nothing" value). To push, move top up one and write there; to pop, read top and move it back down. Nothing ever shifts, so both are O(1) — constant time, no matter how tall the stack is. (New to that? See Big-O.)

Going deeper

limits, trade-offs, and where stacks show up
OperationWhat it doesTime
PushAdd a value on topO(1)
PopRemove and return the top valueO(1)
Peek / TopLook at the top value without removing itO(1)
SearchFind a value somewhere insideO(n)

The two edge cases. Pushing onto a full array-backed stack is an overflow; popping (or peeking) an empty one is an underflow. Both are one-line guard checks. The word "overflow" comes from the real call stack: every function your program calls pushes a frame onto it, and recursion with no stopping condition pushes forever until it overflows and crashes.

Array vs. linked backing. The array version is simple and fast but has a fixed capacity. A linked-list-backed stack removes that limit — push/pop become "add/remove the head node" — at the cost of a pointer per item and an allocation on every push.

Where you'll meet stacks. The function call stack (and therefore recursion itself), undo/redo history, the browser's Back button, matching brackets in a compiler, and depth-first search all run on the same LIFO idea: deal with the most recent thing first.
