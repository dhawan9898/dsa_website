Last In · First Out

Stack

A pile where you can only ever touch the top: add on top, take from the top. That single rule is the whole data structure.

The idea, in one picture

Think of a stack of plates. You add a clean plate on top, and when you need one you take it from the top. You never pull a plate from the middle of the pile, and you never slide one in at the bottom — the top is the only end you touch. A stack the data structure is exactly this: a collection where every add and every remove happens at one end.

That one rule has a name: Last In, First Out, or LIFO. The last plate you put on is the first one you take off. Whatever went in most recently comes out first; the oldest thing sits at the bottom, waiting until everything above it is gone.

Three words for three moves. Push = put a new value on top. Pop = take the top value off (and return it). Peek (or "top") = look at the top value without removing it. That's the entire vocabulary of a stack.

How it actually works

an array + one index

The simplest way to build a stack is the one in the visualizer: take a plain array of a fixed size, and keep a single integer called top that remembers the index of the highest occupied slot. That one number is the whole bookkeeping.

  • When the stack is empty, top is -1 — a made-up "points at nothing" value, since index 0 is already a real slot.
  • To push, move top up by one and write the value there: items[++top] = val. (++top means "add 1 to top first, then use it.")
  • To pop, read the value at top and then move top down by one: items[top--]. The value is still sitting in the array, but top no longer counts it, so it's logically gone.

Notice what doesn't happen: nothing ever shifts. Push and pop change one index and touch one slot, whether the stack holds 3 items or 3 million. That's why both are O(1) — constant time, independent of size. (New to that notation? See Big-O.)

Reading the C

push / pop, line by line

Here is push in C. Don't worry if C is new — every line is spelled out below it.

void push(Stack *s, int val) {
  if (s->top == MAX - 1) return;   // full
  s->items[++s->top] = val;
}
  • Stack *s is a pointer to the stack (its array and its top). The -> arrow means "reach inside the thing this points at" — so s->top is that stack's top index. (The Pointers page explains the arrow.)
  • if (s->top == MAX - 1) return; — if top is already at the last slot, there's no room, so we stop. Pushing anyway would be a stack overflow.
  • s->items[++s->top] = val; — bump top up one, then store val in that slot. One line does both the move and the write.

pop is the mirror image: guard against an empty stack (top == -1), then return s->items[s->top--] — read the top value, then drop top by one.

Going deeper

limits, trade-offs, and where stacks show up
OperationWhat it doesTime
PushAdd a value on topO(1)
PopRemove and return the top valueO(1)
Peek / TopLook at the top value without removing itO(1)
SearchFind a value somewhere insideO(n)

The two edge cases. Pushing onto a full array-backed stack is an overflow; popping (or peeking) an empty one is an underflow. Both are one-line guard checks — and both are classic bugs that only bite at the boundary, in production. The word "overflow" comes from the real call stack: every function your program calls pushes a frame onto it, and recursion with no stopping condition pushes forever until it overflows and crashes.

Array vs. linked backing. The array version here is simple and fast but has a fixed capacity. A linked-list-backed stack removes that limit — push/pop become "add/remove the head node" — at the cost of a pointer per item and an allocation on every push. Same LIFO behaviour either way; only the storage differs.

Where you'll meet stacks. The function call stack (and therefore recursion itself), undo/redo history, the browser's Back button, matching brackets and parentheses in a compiler, and depth-first search all run on the same LIFO idea: deal with the most recent thing first, and let finished work fall away in the reverse of the order it arrived.
