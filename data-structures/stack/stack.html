Last In · First Out

Stack

A collection where you can only ever add to, or remove from, one end — the top.

Notes

A stack holds items in the order they arrived and only exposes one end for both adding and removing: the top. That single rule — Last In, First Out (LIFO) — is the entire definition. There's no reaching into the middle, and no peeking at the bottom.

Because every operation only ever touches the top element, a stack never needs to shift or search anything: push and pop are both O(1), whether the stack holds 3 items or 3 million. Compare that to inserting at the front of an array, which is O(n) because everything after it has to shift over — a stack sidesteps that entirely by only ever touching one fixed end.

Implementation: the visualizer below uses the simplest possible version — a fixed-size array plus a single top index that points at the last occupied slot (-1 when empty). Push writes to items[++top]; pop reads items[top--]. No pointers, no allocation, just one integer doing all the work. The trade-off is a hard capacity limit, fixed when the array is created. A linked-list-backed stack removes that limit — push and pop become "add/remove the head node" instead — at the cost of a pointer's worth of memory per item and a heap allocation on every push.

When it breaks: push past capacity is a stack overflow — the array-backed version here simply refuses once full, but the term comes from the *real* call stack: every function call your program makes pushes a frame onto it, and recursion with no base case overflows it for real, crashing the program. Pop (or peek) on an empty stack is the mirror case, underflow — reading a slot that was never written. Both are one-line guard checks (see the code panel below), and both are exactly the kind of bug that only shows up once, at the edge, in production.

Used constantly under the hood: every function call your program makes is pushed onto a call stack, and returning from it is a pop — that's the mechanism behind recursion itself. Undo/redo history, "back" buttons, matching brackets/parentheses, and depth-first search all lean on the same LIFO idea: handle the most recent thing first, and let finished work fall away in the reverse order it arrived.
