Remove From Either End

Pop (front & rear)

Pop front advances the front; pop rear just shrinks size. Either way it's one index step.

Overview Push (both ends) Pop (both ends) Playground

Pop front: remove the left end

O(1)

Identical to a circular queue's dequeue: read items[front], then advance front = (front + 1) % MAX and drop size. The old front slot is freed for reuse.

  1. Read the value at items[front].
  2. front = (front + 1) % MAX, then size--.

 

Pop rear: remove the right end

O(1)

The rear isn't stored directly — it's computed as (front + size - 1) % MAX. Read that slot, then just shrink size; front doesn't move, and the rear slot is now outside the live range, free to reuse.

  1. Compute rear = (front + size - 1) % MAX and read items[rear].
  2. size-- — that alone drops the rear off the end. front stays put.

 

Why no index reset? Since the live window is defined by front and size together, dropping size is enough to "remove" the rear — there's no separate rear variable to rewind.
