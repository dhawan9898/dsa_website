Double-Ended Queue

Deque

A queue with both ends open for business — insert and delete at the front or the rear.

Notes

A deque ("deck", short for double-ended queue) generalizes both the stack and the queue: it supports inserting and deleting at both ends, each in O(1). Use only the rear for insertion and the front for removal and it behaves exactly like a queue; use only one end for both and it behaves exactly like a stack.

Implementation: the code panel below backs it with a doubly linked list — every node has both a next and a prev, so unlike a plain singly linked list, you can reach backward from any node too. That's what makes inserting or deleting at the rear O(1): a singly-linked list would have to walk all the way to the end first to find the node just before it. (The visualization above still shows the deque as a simple ordered row for clarity — the two prev/next pointers on every real node are what the Doubly Linked List page shows in full.) Never a plain array — inserting at the front of one means shifting every other element down.

When it breaks: deleting the last remaining node and forgetting to null out both front and rear (not just one) leaves the other pointing at freed memory — the next insert then attaches onto a dangling pointer instead of correctly starting fresh.

Sliding-window algorithms (like the classic "maximum in every window of size k") are the textbook use case: values get added at the rear and dropped from either end as the window slides. Browser history and undo/redo stacks that also support "redo forward" reach for the same shape.
