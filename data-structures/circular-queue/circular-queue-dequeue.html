Dequeue: read, then wrap the front forward

O(1)

Dequeue returns the value at front and moves the front forward — but "forward" here means (front + 1) % MAX, so when front is on the last slot it loops back to 0. The slot it leaves is genuinely freed: a later enqueue can compute its way back to it.

  1. Check it isn't empty. If size == 0, there's nothing to remove — stop.
  2. Read the front value at items[front] to return it.
  3. Advance with wrap. front = (front + 1) % MAX, then size--. The old front slot is now free for reuse.

 

No dead space. Because size shrinks and the freed slot is reachable again by the same % MAX arithmetic, nothing is stranded — the flaw of the linear queue is gone.

Peek: look without removing

O(1)

Peek returns items[front] and changes nothing — front and size stay put. It's how you check who's next without advancing the ring.
