Prefix Tree · One Node Per Shared Letter

Trie

A tree built for storing words, where words that share a prefix share the same path from the root.

Notes

A trie (from retrieval, usually pronounced "try") stores a set of strings as a tree where each edge is one character. Start at the root and follow the path spelled by a word's letters, one node per letter; a special flag on a node marks "a word ends here." Because every word that shares a prefix walks the exact same nodes for that prefix, storing car, care, and cart together needs only one path for c-a-r, branching into three separate tails right where the words actually differ.

OperationWhat it doesTime
InsertWalk/create one node per characterO(L)
SearchWalk one node per character, check isEndO(L)
Starts WithSame walk, skip the isEnd checkO(L)
DeleteWalk down, unmark, walk back up pruning dead endsO(L)

L = length of the word — never depends on how many other words are stored.

Implementation: the code panel below gives every node an array of child pointers indexed by letter (children['a'..'z']) plus an isEnd flag. search and startsWith are almost the same function — the only difference is what they check once the walk finishes: a search demands isEnd, a prefix check is satisfied just by the path existing at all. That distinction matters: after inserting only "car", searching for "ca" correctly fails (it's a prefix, not a stored word) while startsWith("ca") correctly succeeds.

Common mistake: deleting a word by just unmarking its final node's isEnd flag and stopping there leaves every node on its path allocated forever, even ones no other word needs — a slow memory leak. The fix is walking back up from the deleted word's end, freeing each node whose subtree is now completely empty, but stopping the moment a node is either the end of a different word or still has another child — deleting "care" after also inserting "car" must stop pruning at the shared r, not remove it.
