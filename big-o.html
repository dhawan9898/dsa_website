Big-O Notation

How to read every O(...) badge on this site — what it measures, why constants drop out, and which shape each class belongs to.

Notes

Big-O notation describes how an algorithm's running time (or memory use) grows as its input size, n, grows — not how many milliseconds it takes on any one machine. "O(n²)" doesn't mean "this takes n² seconds"; it means "double the input, and expect roughly four times the work." That's what every badge on this site — O(1), O(log n), O(n log n) — is reporting.

Two simplifications make this useful instead of exact. First, constants drop out: an algorithm that does 3n + 5 operations is still O(n), because what dominates once n is huge is the n, not the 3 or the 5. Second, only the fastest-growing term survives: O(n² + n) is just O(n²), since the n² term swamps the n term as n grows. Big-O is deliberately a blunt instrument — it answers "does this get dramatically worse with more data?", not "exactly how many nanoseconds?".

Most badges on this site report worst case — the guarantee that holds no matter what input you throw at it. A few are labelled "average" instead, because their worst case is rare but real: a hash table where every key collides into one bucket, or quicksort handed an already-sorted array with a naive pivot, both degrade to O(n) or worse. "Average" isn't a loophole — it's an honest label on a slower path that's still there.
