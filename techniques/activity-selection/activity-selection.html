Greedy · Sort · Scan · Never Reconsider

Activity Selection

Given a set of activities with start and end times, pick the largest possible group that never overlaps.

Notes

One resource — one meeting room, one server, one runway — and a list of activities, each wanting it for a fixed [start, end) window. Two activities conflict if their windows overlap (touching at a single instant, one ending exactly when the next begins, is fine). The goal: schedule the maximum number of activities with no conflicts. Unlike N-Queens, there's no need to explore and undo — a single greedy pass, made safe by the right sort order, solves it exactly.

Implementation: sort every activity by finish time, earliest first. Then scan once, left to right, keeping a running lastEnd — the finish time of the most recently selected activity. Any activity whose start is at or after lastEnd gets selected (it can't conflict with anything already chosen); anything else is skipped for good and never reconsidered. That's the entire algorithm: one sort, one pass, no backtracking.

Sort by finish timeqsort on endO(N log N)

Why finish time, specifically: the activity that finishes soonest can always be part of some optimal schedule — whatever an optimal solution picked for that first slot, swapping in the earliest-finishing activity instead leaves at least as much room for everything after it, so it can never make the schedule worse. Repeating that argument on whatever's left after each pick is what makes the greedy choice safe at every step, all the way through — no combination of "skip this one, take two later" can ever beat it.

Common mistake: sorting by duration instead, on the intuition that shorter activities leave more room. It's a natural guess and a classic trap. Take A(0–3), B(2–4), C(3–6): B is shortest (length 2, versus 3 for the others), but B conflicts with both A and C, so picking it first — and never reconsidering, same as any greedy pass — strands you at just 1 activity. Sorting by finish time instead picks A first (it finishes at 3), correctly skips B (starts at 2, before A ends), and still catches C (starts at 3, exactly when A ends) — 2 activities, the true optimum. Sorting by start time fails the same way, for the same reason: neither says anything about how much room a pick leaves behind.

Space is just O(N) for the sorted copy — no recursion, no call stack growing and shrinking, which is the clearest contrast with N-Queens' backtracking search: a greedy algorithm never explores more than one path, because it never needs to look back.
