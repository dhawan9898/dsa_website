Halve the Range Every Step

Binary Search

Requires sorted data. Compares the target to the middle of the current range and throws away the half that can't possibly contain it — again and again.

Notes

Binary search trades linear search's total freedom for speed: it only works on sorted data, but that ordering is enough to eliminate half the remaining range with a single comparison. Compare the target to the value at the middle of the current [lo, hi] range — if they match, done; if the target is bigger, it can only be to the right, so everything from lo to mid is eliminated in one stroke; if smaller, the mirror image on the left. Repeat on whatever range is left.

Implementation: the code panel below keeps lo and hi as the only state, recomputing mid fresh every iteration — nothing about the range needs to be copied or rebuilt, which is what keeps this version O(1) space (a recursive version would spend O(log n) on the call stack instead). Every single comparison discards roughly half of what's left, so even a sorted array of a billion elements takes at most about thirty comparisons.

Common mistake: computing the midpoint as (lo + hi) / 2 can overflow in languages with fixed-width integers once lo + hi exceeds the integer range, even though neither lo nor hi alone is out of range. The safer form is lo + (hi - lo) / 2, which never adds two large numbers together. The other classic bug is the loop condition itself: lo < hi instead of lo <= hi silently skips checking the case where exactly one element remains.
