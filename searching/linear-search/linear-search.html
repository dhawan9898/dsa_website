Check Every Index, In Order

Linear Search

Walks the array from the front, checking each value against the target until it finds a match or runs out of array. Works on any array, sorted or not.

Notes

Linear search is the baseline every other search algorithm improves on: check index 0, then 1, then 2, and so on, until the target turns up or the array runs out. It needs no assumption at all about how the data is arranged — it works identically on a sorted array, a shuffled one, or one full of duplicates. That generality is exactly why it's slow: with no ordering to exploit, there's no way to rule out large chunks of the array without actually looking at them.

Implementation: the code panel below is about as short as an algorithm gets — one loop, one comparison, one early return. That simplicity is the whole point of having it on this site: every other search algorithm here is a strategy for skipping comparisons that linear search cannot skip, precisely because it assumes nothing about the data.

Common mistake: continuing to scan after a match instead of returning immediately wastes comparisons on an array with a unique target, but matters more with duplicates — if the array can contain the target more than once and you need the first occurrence specifically, an early return is what guarantees that, not an afterthought.
