Check Every Index, In Order

Linear Search

The most basic search: look at each element in turn until you find what you want — or run off the end.

Overview Playground

The idea, in one picture

Looking for a name in an unsorted list, you have no choice but to read down the list one entry at a time until you hit it. That's linear search: start at the first element, compare, move to the next, and stop the moment you find a match (or when you've checked them all and it isn't there).

Its one superpower: no assumptions. Linear search works on any list — sorted or not, array or linked list — because it just walks straight through. That generality is why it's the fallback when faster searches (which need sorted data or an index) don't apply.

Going deeper

cost and when to use it
CaseWhenTime
BestTarget is firstO(1)
Average / WorstMiddle / last or absentO(n)
SpaceNo extra memoryO(1)

If the data is sorted, binary search finds the target in O(log n) — dramatically faster — and jump search sits in between at O(√n). But those require sorted input; linear search is the honest O(n) baseline that always works, and it's the right choice for small or one-off searches where sorting first wouldn't pay off.
