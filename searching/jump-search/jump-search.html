Jump in Blocks · Scan the Last One

Jump Search

Requires sorted data. Leaps forward in fixed-size blocks to find where the target must live, then falls back to a plain scan inside just that block.

Notes

Jump search sits between linear search and binary search. Like binary search it needs sorted data, but instead of always halving the range, it leaps forward in fixed-size blocks — checking only the last element of each block — until it finds a block whose last value is ≥ the target. Since the array is sorted, the target (if present) has to be somewhere in that one block, so the final step falls back to an ordinary linear scan, but only across that single block instead of the whole array.

CaseTime
Every caseO(√n) with block size √n
SpaceO(1)

Implementation: the code panel below picks a block size of √n specifically because it's the size that minimizes the total work: jumping costs at most n/blockSize probes, and the final scan costs at most blockSize more, and n/blockSize + blockSize is smallest exactly when blockSize = √n. That balance is the entire reason jump search exists — it was designed for tape and disk drives where a long jump was cheap but a full binary search's scattered, unpredictable probing pattern was expensive.

Common mistake: forgetting to clamp the final block's upper bound to n — the last jump can land past the end of the array if n isn't an exact multiple of the block size, and scanning (or even just indexing) past the array's actual length is undefined behavior in C, not a graceful "not found."
